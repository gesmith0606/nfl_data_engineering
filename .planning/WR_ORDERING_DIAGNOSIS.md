# WR Ordering-Loss Diagnosis (2026-08-09)

Why does our WR weekly rank **order** lose to Sleeper (+0.375 FantasyPros-style
Accuracy Gap this run — matches the documented ~0.35, worst position) while our
WR point **MAE beats** both Sleeper and ESPN? Decomposes the ordering loss five
ways. Generated by `scripts/diagnose_wr_ordering.py`, which imports
`scripts/simulate_fp_accuracy.py`'s rank/baseline/Accuracy-Gap machinery
directly (`load_ours`, `load_consensus`, `attach_actuals`, `score_all`) rather
than recomputing it — the only change to that file was making `score_all()`
also return its already-computed row-level frame (`full`: per player-week
rank, actual_rank, accuracy_gap, in_pool flag) instead of discarding it after
aggregation.

**Data**: `output/backtest/backtest_half_ppr_consensus_20260809_145355.csv`
(regenerated this session — the CSV named in the task,
`..._20260808_235409.csv`, was gone from the gitignored `output/backtest/`
dir; same command from `FP_ACCURACY_SIMULATION.md` reproduces it). WR,
weeks 3-17, 2022-2024, both sources in the FantasyPros top-50 pool:
2,713 matched player-weeks.

**Self-check**: the script's own WR/ours and WR/sleeper aggregate (computed by
re-deriving the two-level weekly-then-season mean from `full`) is asserted
equal (< 1e-6) to `simulate_fp_accuracy.summarize()`'s canonical number before
any slicing runs — confirms the row-level frame this diagnosis is built on is
the *same* population `simulate_fp_accuracy.py` already certified, not a
lookalike.

Key point that makes several of these findings clean: Accuracy Gap =
`|baseline(rank) - actual_points|`, and `actual_points` is identical across
sources for a given player-week. So `our_gap - sleeper_gap` for one
player-week is attributable **entirely to the rank each source assigned**
(ordering), never to point magnitude. That identity is what lets findings 1
and 3 below double as direct "ordering damage" measurements.

## Findings, ranked by actionability

### 1. Early season (weeks 3-6) is again the dominant driver — same root cause as the RB/QB report, now confirmed for WR ordering specifically

| Season | Weeks 3-6 gap_diff (n) | Weeks 7-12 gap_diff (n) | Weeks 13-18 gap_diff (n) |
|---|---|---|---|
| 2022 | **+0.969** (251) | +0.580 (352) | +0.139 (306) |
| 2023 | +0.482 (238) | +0.313 (360) | +0.110 (302) |
| 2024 | **+0.625** (243) | +0.106 (360) | +0.234 (301) |

`gap_diff = our_gap - sleeper_gap`, positive = we lose. All six weeks-3-6/
weeks-13-18 comparisons show weeks 3-6 worse, by 2-7x, all reliable (n
238-251). This is the same shape as `CONSENSUS_ERROR_DECOMPOSITION.md` finding
#1 (which showed weeks-3-6 MAE weakness for RB/WR/TE vs both sources) — this
diagnosis shows the *ordering* component specifically inherits it, and it's
the single largest slice-level effect found here. The swap-analysis examples
(finding 2) independently cluster in exactly these weeks (2023 W5, 2024 W3/W5
dominate the worst-actual-diff swap losses), which is a second, independent
line of evidence for the same conclusion.

**Mechanism**: with only 1-3 games of current-season history in weeks 3-6,
our rolling-average-driven rank is still anchored close to a
preseason/depth-chart prior that hasn't absorbed early-season role signals
(a breakout target share, a new QB connection, a committee resolving) —
Sleeper's consensus apparently incorporates faster-moving inputs (beat
writer/analyst adjustments) that reorder players sooner.

**Lever**: this is the same lever already proposed in
`CONSENSUS_ERROR_DECOMPOSITION.md` #1 — a shrinkage-toward-prior-season-PPG
scheme for weeks 3-6 with weight decaying as current-season sample grows.
Notably `--early-season-prior` (see `EARLY_SEASON_PRIOR_GATE.md`) already
exists as an opt-in flag covering exactly weeks 3-6, QB/RB/WR/TE — this
diagnosis is independent evidence it should specifically help WR **ordering**,
not just WR MAE, since the mechanism (thin-sample rank instability) is the
same one driving both.

### 2. Swap-loss pairs are near-ties in OUR projections but not in actual outcome — a compressed local-ordering problem, not random noise

Pairwise comparison across all in-pool WR pairs each week (80,123 pairs;
7,132 = 8.9% are "swap losses": we order A>B, Sleeper orders B>A, and B
actually outscored A):

| Metric | All pairs | Swap-loss pairs |
|---|---|---|
| Median \|our_diff\| (our own projection gap between A and B) | 3.51 | **1.21** |
| Median \|sleeper_diff\| | — | 1.28 |
| Median \|actual_diff\| (real outcome spread) | 5.8 | 6.1 |
| Same-team share | 2.5% | 1.8% |

The median projection gap between two WRs *in our own rankings* is 3x smaller
for the pairs we misorder (1.21 vs 3.51 pts) than for pairs generally — these
are genuinely close calls for our engine specifically. But the actual outcome
spread on those same pairs is **not** small (median 6.1 pts, in line with the
overall 5.8 median) — these aren't coin-flip weeks where nobody could have
called it; Sleeper called the same pair correctly with an equally tight
projection gap (1.28), so it isn't that Sleeper had dramatically more
separation either. Same-team share is not elevated (rules out a
single-backfield-target-competition explanation). Manually inspecting the
worst swap losses by \|actual_diff\| shows them clustering in the same weeks
3-6 window as finding #1 (2023 W5: C.Sutton/D.Moore/N.Collins vs J.Chase's
44-point week; 2024 W3/W5: R.Doubs/L.McConkey/J.Jennings vs breakout games) —
i.e. this finding and finding #1 substantially overlap rather than being two
independent causes.

**Mechanism**: our engine assigns two players nearly identical point
projections in a pool where the true outcomes will actually separate by
several points — a genuine local-ordering weakness among closely-projected
players, concentrated where the underlying signal (early-season role/target
share change) hasn't been absorbed yet.

**Lever**: same lever as #1 for the early-season overlap. For the residual
that isn't week-3-6 specific (2023/13-18 gap_diff is still +0.11, nonzero),
a tie-breaking feature — e.g. recent target-share trend or snap-share trend
as a secondary sort key when two WRs are within ~1-2 projected points of each
other — would directly attack this local-ordering weak spot without touching
overall point calibration (preserving the MAE win).

### 3. Ordering damage concentrates in a small, identifiable list of "sticky prior" veteran WRs — not diffuse noise

Top-20 cumulative-damage players (sum of our_gap − sleeper_gap across their
weeks) account for a large share of the total WR gap; the list is dominated
by established/name-brand WRs whose role or production declined
mid-2022-2024 relative to reputation: **A.Brown** (n=37, damage +79.5, our
mean rank 5.1 vs Sleeper 6.0 vs actual 19.4), **D.Hopkins** (+62.7),
**M.Pittman** (+53.9), **G.Wilson** (+51.2), **T.Hill** (+42.6),
**D.Metcalf** (+42.0), **N.Collins** (+37.0), **D.Moore** (+34.4),
**J.Waddle** (+34.8), **T.McLaurin** (+27.5) — nine of the top eleven are
established veteran WRs the field (and probably our rolling-average features)
still treats as elite by track record, most of whom under-delivered relative
to that reputation in-sample.

A caveat worth being honest about: the table reports *mean* rank per player
across their weeks, which can mask week-to-week volatility (e.g. D.Hopkins'
mean rank is actually slightly *more* conservative than Sleeper's — 26.6 vs
21.4 — yet still contributes positive damage, which the mean alone doesn't
explain; the underlying weekly rank swings likely matter more than the
average, and this per-player table shouldn't be read as "we always overrate
this exact player by this exact amount every week"). A.Brown, M.Nabers
(rookie, n=10, our rank 5.6 vs Sleeper 14.1, actual 18.9), and Z.Flowers are
the cleanest, most directional cases (we are unambiguously more bullish than
Sleeper on average, in weeks where the player underperformed both).

**Mechanism**: likely the same "rolling-average anchored to reputation, slow
to downgrade" pattern already documented for RB in
`CONSENSUS_ERROR_DECOMPOSITION.md` #2/#4 (committee-back role changes lag a
season-long rolling average), applied here to established WRs whose role
degraded (target competition, scheme change, injury-limited snaps) faster
than a trailing-average feature adjusts.

**Lever**: same family as the RB lever already proposed — a
faster-reacting opportunity/target-share-trend feature (short window, e.g.
last-2/3-game snap or target share vs season-long) would give the engine an
earlier signal to downgrade a declining veteran instead of relying on a
season-long rolling average that lags. Lower confidence than #1/#2 since it's
n=20 players, not a clean reliable-slice statistic — treat as a shortlist for
qualitative review (are these specifically stale-feature cases?) rather than
a slice-level lever on its own.

### 4. Compression hypothesis — tested and NOT confirmed; ruled out as the primary driver

| Source | Mean adjacent-rank gap (top-50 pool) | proj_std | proj_IQR |
|---|---:|---:|---:|
| Ours | 0.213 | 2.593 | **3.777** |
| Sleeper | 0.220 | 2.683 | 3.621 |

Our WR projection curve is **not** meaningfully flatter than Sleeper's — mean
adjacent-rank spacing is within 3% of Sleeper's, our IQR is actually
*wider*, and our std is only slightly lower. If ordering loss were explained
by "we compress projections into too narrow a band, so ranks flip on noise,"
this table would show a materially smaller ours-vs-sleeper spread; it
doesn't. **This rules out global under-dispersion as the explanation.** The
loss is better explained by findings #1-3: it's not that our WR list is flat
everywhere, it's that specific players/weeks (early season, declining
veterans) are locally mis-ordered while overall spread is fine. Do not spend
effort on a "widen the distribution" lever — it would not address the actual
mechanism and risks hurting the MAE win that currently exists.

### 5. Rank-curve position — losses concentrate at the top (elite tier) and in the "overranked bust" tail, not the mid-pack

| Tier (by actual finish) | n | our_gap | sleeper_gap | gap_diff |
|---|---:|---:|---:|---:|
| WR1-12 (elite) | 540 | 9.813 | 9.139 | **+0.675** |
| WR13-30 | 810 | 6.041 | 5.812 | +0.229 |
| WR31-50 | 900 | 4.941 | 4.738 | +0.203 |
| WR51+ (ranked top-50 by us/Sleeper, busted) | 463 | 8.013 | 7.411 | **+0.602** |

All four tiers reliable (n 463-900). The bulk of the pool (WR13-50, the
middle two rows) shows a much smaller gap_diff (~0.2) than the two tails
(~0.6-0.7). The elite tier has the largest raw gaps for *both* sources
(baseline points at rank 1-12 are large and outcome variance is high at the
top of the position, so both sources' Accuracy Gaps are naturally bigger
there) but ours is worse by the largest absolute margin of any tier. The
WR51+ tail (players either source ranked in their own top-50 who then missed
the actual top-50 that week) is the second-worst tier — this is functionally
the same population as the "sticky prior" veterans in finding #3 (established
names ranked confidently who then underperformed).

**Mechanism**: at the very top, ordering errors among the 5-10 true difference
-makers are disproportionately expensive under this metric because the
baseline point curve is steep near rank 1 (small rank swaps near the top move
the baseline value more than the same swap does mid-pack) — consistent with
finding #2's "near-tie in our projections, real separation in outcome" being
most costly exactly where the position's few true elites live.

**Lever**: lower priority as a standalone lever (it's largely explained by
#1-3, not a new independent mechanism) but useful as a validation target —
after implementing the weeks-3-6 shrinkage (#1) and/or a target-share
tie-break (#2), re-run this rank-curve table and check whether the WR1-12 and
WR51+ gap_diff shrink toward the WR13-50 baseline (~0.2); if they don't, the
elite-tier problem is separate (e.g. genuinely under-weighting workhorse-role
signals for the true top tier) and needs its own investigation.

---

## Bottom line

1. **Weeks 3-6 early-season thin-sample instability is the dominant, most
   actionable driver** (finding #1) — already has a candidate fix built
   (`--early-season-prior`); this diagnosis adds evidence it should help WR
   *ordering* specifically, not just MAE, so it's worth re-running this exact
   script with that flag's backtest output once evaluated.
2. **Swap losses are a compressed-local-ordering problem concentrated in the
   same early weeks**, not general noise — a target/snap-share-trend
   tie-breaker for near-tied WR pairs is the next-best lever if #1 alone
   doesn't close the gap.
3. **A short list of established/declining veteran WRs (A.Brown, Hopkins,
   Pittman, Wilson, Hill, Metcalf, etc.) account for a large share of total
   damage** — worth a qualitative check of whether these are stale-feature
   cases before building a dedicated feature; same underlying root cause as
   the RB committee-back finding in `CONSENSUS_ERROR_DECOMPOSITION.md`.
4. **The compression hypothesis is ruled out** — do not pursue a
   "spread out the distribution" fix; our WR projection dispersion is
   already comparable to Sleeper's.
5. Rank-curve tiering shows the loss concentrates at the elite tier and the
   overranked-bust tail — treat as a validation checkpoint for #1-3, not an
   independent lever.

## Addendum (2026-08-09): `--early-season-prior` re-scored on the ordinal (FP Accuracy Gap) metric

Follow-up to finding #1 above. `.planning/EARLY_SEASON_PRIOR_GATE.md` gated
lever #1 (weeks-3-6 shrinkage toward prior-season PPG) on **MAE** and landed
**HOLD** (weeks-3-6 MAE gap vs Sleeper improved 0.023 pts, needed ≥0.10). This
addendum re-scores the same lever on the **ordinal FantasyPros Accuracy Gap**
metric this report is built around, since finding #1 predicted it should help
ordering specifically, not just MAE.

**Pre-registered gate** (stated by the coordinator before any treated numbers
were computed): SHIP-for-ordering if the overall (QB+RB+WR+TE mean, weeks
3-17) Accuracy Gap vs Sleeper improves ≥0.05, **with WR improving** and **no
position worsening >0.03**; else HOLD stands.

  (regenerated this session for the main diagnosis above; same command as

almost entirely carried by the 2023/2024 rows. Worth fixing (ingest
`season=2021` player_weekly) before trusting a 3-season average of this lever
again.

### Verdict: **HOLD** (ordinal metric — consistent with the MAE-based gate)

The pre-registered composite gate requires all three criteria; criterion 1
(overall Accuracy Gap vs Sleeper improving ≥0.05) fails at a measured
**−0.018**, roughly a third of the bar, even though it's the right sign and
even though the WR-specific and rank-tier cuts show a real, sometimes
substantially larger, effect within the weeks-3-6 window it targets. This
independently corroborates `EARLY_SEASON_PRIOR_GATE.md`'s HOLD on a second,
unrelated metric (ordinal instead of MAE) — do not flip `--early-season-prior`
on by default based on either metric. It remains valid opt-in/evaluable
machinery.

**Follow-ups**, in addition to `EARLY_SEASON_PRIOR_GATE.md`'s existing list:
1. Ingest `data/bronze/players/weekly/season=2021` so the 2022 backtest row
   stops being a mechanical no-op — the current 3-season average is really a
   2-season signal wearing a 3-season label.
2. The weeks-3-6-only WR effect (−0.14 to −0.20) is meaningfully bigger than
   the diluted full-season number (−0.027) — if a future iteration
   specifically targets weeks 3-6 evaluation (rather than a weeks-3-17
   season average) as its gate population, this lever looks more promising
   than the current gate verdict suggests. Worth deciding whether the gate
   *should* be scoped to the target window before the next re-run, rather
   than always diluting into the full season.
