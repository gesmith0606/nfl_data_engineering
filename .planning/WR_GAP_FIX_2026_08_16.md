# WR Gap Fix — 2026-08-16

Follow-up to `.planning/HYBRID_SHIP_2026_08_15.md` §5 (WR stayed the one position
losing to consensus after the QB/RB/TE hybrid-ML ship) and
`.planning/RETRAIN_ON_REPAIRED_FEATURES.md` (WR retrain on repaired
snap_pct/NGS/PFR/QBR features REGRESSED vs the shipped model). Task: find why
the WR retrain regressed, and close the remaining gap. Pre-registered gate:
WR 2022-24 matched-pairs gap vs Sleeper AND ESPN ≤ 0 (outright win) with
sealed-2025 WR MAE not worse than shipped by >0.02. Secondary target: WR
FP-ordinal gap vs Sleeper improves ≥0.05.

**Verdict: GATE PASSES.** Shipped a 60/40 blend of the existing shipped WR
Ridge with a same-recipe retrain on the repaired features **using the same
unfiltered training population the shipped model saw** (weight tuned on
2022-24 walk-forward only; sealed 2025 touched only for the final gate read).

## 1. Root cause of the retrain regression

`MODEL_REVIEW_2026_08_15.md` finding #4 flagged it and this task confirms it
directly: **training population, not feature schema, is the delta.**

`_filter_eligible_players()` (`src/player_feature_engineering.py:469`) keeps
QB/RB/WR/TE rows with `snap_pct_roll3 >= 0.20`, but falls back to
"position only" (every skill-position row, no snap-share floor) whenever
`snap_pct_roll3` is entirely NaN:

```python
if "snap_pct_roll3" in df.columns and df["snap_pct_roll3"].notna().any():
    mask_snap = df["snap_pct_roll3"] >= 0.20
else:
    logger.warning("snap_pct_roll3 unavailable; filtering by position only")
    mask_snap = True
```

The shipped WR Ridge (committed 2026-06-12) was trained back when
`snap_pct_roll3` was **100% NaN everywhere** (the name-join bug documented in
`SILVER_REGEN_REPORT.md` — abbreviated vs full player names, 0% match since
inception) — so it silently trained on the **unfiltered** population (every
WR-position row, deep bench included). The 2026-08-15 retrain used the same
`assemble_multiyear_player_features` pipeline, but by then the join was
fixed and `snap_pct_roll3` carries real values — so that retrain silently
trained on the **filtered** population (only rows with ≥20% trailing snap
share) for the first time ever, with no explicit decision to change it.

Directly confirmed by re-deriving the last training season's mask under the
current code: WR position rows before the filter for 2024 alone = 2,132; after
the (now-live) 20%-snap filter = 1,675 (21% removed). Full 2016-2024 window,
same population definitions: unfiltered = 16,440 rows, filtered
(2026-08-15 retrain, matches `models/retrained_2026_08_15/wr_residual_meta.json`)
= 13,591 rows, shipped (June, unfiltered but an older/narrower Bronze
snapshot and season window) = 10,733 rows. The June/August row-count
mismatch beyond the filter itself (10,733 vs the 16,440 an unfiltered rerun
of *today's* full 2016-2024 window produces) is real but not chased further
here — the filter's on/off state is the reproducible, code-visible lever;
residual differences in exact row counts come from Bronze/Silver having
grown since June, which is expected and not the mechanism under test.

**Why would training on deep-bench-included rows help?** Working hypothesis
per the task brief: broader receiver-role context (backups, committee/timeshare
receivers, players who later become the eligible WR2/WR3 pool) gives Ridge more
of the outcome distribution to calibrate against, which matters for a linear
model more than a tree model. Not independently verified beyond the
population-swap result itself (Experiment 1 below) — flagged as a good
follow-up if a future WR effort wants to understand *why*, not just *that*.

## 2. Experiments (same-session baseline + treated, walk-forward 2022-24 for
tuning, sealed 2025 touched only for final gate reads)

Harness: `run_backtest(seasons, weeks=None, "half_ppr", use_ml=True,
full_features=True)` from `scripts/backtest_projections.py` (the real
production path — `ml_projection_router.generate_ml_projections` →
`hybrid_projection.apply_residual_correction`, model files swapped into
`models/residual/wr_residual.joblib` for the duration of each run, then
restored), run per 2-season chunk to stay foreground/<10min per call. Matched
population fixed by construction (`consensus_proj >= 5`, weeks 3-18,
`join_consensus` inner join) — only our own `projected_points` changes
between configs, so all rows compared are byte-identical across experiments.
Harness sanity-check: baseline (shipped, unmodified) reproduces
`HYBRID_SHIP_2026_08_15.md` §7 within rounding — vs Sleeper +0.0062 (doc:
+0.007), vs ESPN −0.0376 (doc: −0.037).

QB/RB/TE untouched in every experiment (only `wr_residual*` files were ever
swapped) — no re-verification needed beyond that structural guarantee.

### Experiment 1 — retrain WR on repaired features + UNFILTERED population (tests the root-cause hypothesis directly)

`train_and_save_residual_models(positions=['WR'], model_type='ridge',
shap_feature_count=60, training_seasons=2016-2024)` with
`_filter_eligible_players` monkey-patched to the position-only mask (mimics
what the shipped model saw). Selected features: 22/60 are repaired
NGS/PFR/snap_pct features (same order of magnitude as the 2026-08-15
filtered retrain's 22/60) — feature schema is comparable, population is the
only deliberate difference from that prior (failed) retrain.

| Config | 2022-24 vs Sleeper | 2022-24 vs ESPN | Sealed-2025 MAE (bias) |
|---|---:|---:|---:|
| Shipped (baseline) | +0.0062 (thin loss) | −0.0376 (win) | 3.8205 (+0.033) |
| **Exp 1: unfiltered pop + repaired features** | **−0.0125 (win)** | **−0.0562 (win)** | 3.8582 (+0.240) |
| Δ vs shipped | −0.0187 | −0.0186 | **+0.0377 (fails ≤0.02 tolerance)** |

Confirms the hypothesis cleanly: restoring the unfiltered population flips
the matched-pairs consensus gap to an outright win vs **both** sources — but
sealed-2025 MAE degrades by +0.038 (bias triples, 0.033→0.240), missing the
≤0.02 non-degradation gate on its own. Unfiltered population is the lever
that fixes ordering/consensus-relative accuracy; it also shifts the sealed
calibration in a way the shipped model's narrower population didn't.

## 4. Implementation

`src/hybrid_projection.py::apply_residual_correction()` — added an optional
secondary-model blend, gated purely by two new meta keys
(`blend_secondary_dir`, `blend_weight`), applied after the existing
clip/floor/round logic:

```python
blend_dir = meta.get("blend_secondary_dir")
blend_weight = meta.get("blend_weight")
if blend_dir and blend_weight:
    secondary_result = apply_residual_correction(
        heuristic_projections, player_features, position, model_dir=blend_dir
    )
    blended = primary_pts * (1 - blend_weight) + secondary_pts * blend_weight
    result["projected_points"] = blended.round(2)
```

Recursive call reuses all existing logic (graph-feature enrichment, clip,
floor, dedup) for the secondary model — no duplicated code path. No-op for
any meta without these keys, so QB/RB/TE and any future plain WR/TE model
are unaffected; `src/ml_projection_router.py` needed **zero changes** (the
blend lives entirely inside `hybrid_projection.py`, invoked through the
existing `apply_residual_correction` call site).

Artifacts:

  2026-06-12 Ridge.
- `models/residual/wr_residual_meta.json` — gained
  `"blend_secondary_dir": "models/residual_wr_secondary"`,
  `"blend_weight": 0.4`.
- `models/residual_wr_secondary/wr_residual{.joblib,_meta.json}` — new,
